## 4. Exact command sequence for the deterministic CI suite

Runtime pins: `.nvmrc:1` (24.18.0) and `package.json:40-42`. Lane selection: `scripts/ci/plan.mjs:106-112` (push, schedule, dispatch, or `ci:full` label runs the full baseline). PR diffs are classified at `plan.mjs:113-172`. Test-only changes still set `code=true` (`plan.mjs:129-132`), so the full four-shard suite runs (docs/testing.md:840-843).

**Static job** (`ci.yml:77-98`, ubuntu-latest):

1. `npm ci` (`ci.yml:92`).
2. `npm run check:ci` (`ci.yml:94`). `package.json:115` expands to `node scripts/run-exclusive.mjs artifacts turbo run typecheck lint:built format:check knip metadata:check jscpd scan:todos && npm run verify:architecture-guards`. npm runs `precheck:ci` first (`package.json:114`, `deps:check`).
3. `npm run verify:test-discovery` (`ci.yml:96`; `package.json:250`).

**Build job** (`ci.yml:133-198`, ubuntu-latest): 4. `npm ci` (`ci.yml:147`). 5. Composite cache `.github/actions/portable-build-cache` (`ci.yml:149`). It keys on `npm run --silent test:prepare -- --dry=json` (`action.yml:16`) and restores or saves `.turbo/cache/`. 6. `npm run test:prepare` (`ci.yml:152`; `package.json:270`). This runs `check-dependency-install` and `turbo run artifacts:mcp-catalog artifacts:product-catalog artifacts:managed-evidence`. Those depend on `compile` (tsc and bundle-runtime, `turbo.json:5-22`) and `artifacts:skills` (`turbo.json:106-175`). 7. Optional default-branch timing fetch (`ci.yml:153-174`, `continue-on-error`). 8. Upload `rea-test-runtime` (`ci.yml:175-187`).

**Test-shard job**, four shards `1/4` to `4/4` (`ci.yml:100-131`): 9. `npm ci` (`ci.yml:115`); download `rea-test-runtime` (`ci.yml:116-119`). 10. `REA_CI_TEST_HISTORY=.cache/ci-test-history/test-results.json npm run test:ci:shard:run -- --shard=N` (`ci.yml:120-122`). This runs `package.json:147`: `vitest run --coverage.enabled --coverage.provider=v8 --coverage.thresholds.*=0 --reporter=default --reporter=blob`. CI calls `:run` directly to skip `pretest:ci:shard` (`package.json:145`, which would run `test:prepare` again). 11. Upload `.vitest/blob/*` (`ci.yml:123-131`).

**Test (merge) job** (`ci.yml:200-271`, ubuntu-latest): 12. `npm ci` (`ci.yml:222`); download `vitest-report-*` blobs into `.vitest/blob` (`ci.yml:223-228`). 13. `npm run test:ci:merge -- --coverage.reportsDirectory=coverage --coverage.reporter=text --coverage.reporter=json-summary --coverage.reporter=lcov --reporter=default --reporter=junit --reporter=json --outputFile.junit=test-results.xml --outputFile.json=test-results.json` (`ci.yml:231-241`). This runs `package.json:148`: `vitest --merge-reports --coverage.enabled --coverage.provider=v8`. The global and per-glob thresholds in `vitest.config.ts:189-206` apply here. 14. Slowest-file summary to `GITHUB_STEP_SUMMARY` (`ci.yml:242-261`); upload `test-results` and `coverage/` (`ci.yml:262-271`).

**Gate:** `node scripts/ci/required.mjs` (`ci.yml:673`) fails if any selected lane did not succeed (`scripts/ci/required.mjs:3-24`).

**Docs lane** (deterministic, related): `npm ci` (`ci.yml:561`), `npm run docs:check` (`ci.yml:562`; `package.json:231-232`: metadata, skill, product-catalog, completion-ledger, doc-facts, and error-schema `--check`), then `git diff --exit-code` (`ci.yml:564`).

## Summary: what a Linux container with Node 22.19+ and npm can run deterministically

Prerequisite: `npm ci` needs registry access or a warm npm cache. Some checks also need `git` on PATH.

Runnable with no extra tools:

- Static checks (`check:ci` components): typecheck, oxlint and module boundaries, oxfmt check, knip, metadata check, jscpd, scan:todos, `verify:architecture-guards` (`package.json:115`). `verify:test-discovery` and the lint module-boundary step need `git`.
- Build and artifacts: `build:cached` and `test:prepare` (turbo, Node only).
- Vitest suite: `test:run`, or the four CI shards plus merge (`package.json:130`, `:147-148`). Tests were not executed here, and CI pins Node 24.18.0, so Node 22 is unverified.
- Docs: `docs:check` (`package.json:231`).
- Verifiers: `verify:managed`, `verify:inspector`, `verify:javascript:digests` (heavy memory), `verify:javascript:output` (disk), `verify:test-temp-hygiene`, `verify:package` (warm npm cache).
- `verify:windows-native:artifact` only if a prebuilt PE is supplied.

Runnable with stock Linux tools (cc, nm; no Hopper, Ghidra, or browser): `verify:fixtures` (CI runs it with no `npm ci`, `ci.yml:273-282`) and `verify:readiness`.

Needs operator-supplied inputs: `verify:application-workflows`, `verify:javascript-runtime`, and `verify:harmony` (HAP pre-fetched from the network).

Not runnable here without external engines, OS, or network: all remaining `verify:*` lanes (Hopper, Ghidra, IDA, JEB, JADX, Binwalk and Unblob, WABT, Android SDK, Chromium, Electron, Termux, macOS, Windows, third-party clients, Codex, npm publish), and every workflow except `ci.yml` static, build, test, docs, and required, which need only Node, npm, and git.
