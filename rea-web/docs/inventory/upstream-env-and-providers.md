# Runtime environment names and provider requirements (SaaS-Cloner)

Scope: `/home/user/SaaS-Cloner`, an import of morluto/rea at commit `c22111eca2c4bc84a084f12711f405b3e7422a40` (HEAD verified). Read-only: no file in the repository was modified. Paths are repo-relative; `docs/` line numbers refer to the Markdown guides.

## Method

- Name index: `REA_[A-Z0-9_]+` across `src/`, `scripts/`, `tests/`, `bridge/`, `native/`, `.github/`: 1,382 distinct (token, file:line) hits, 252 distinct tokens.
- Runtime set: non-test `src/` plus `scripts/rea.mjs`. This yields 45 distinct tokens. 37 are environment variables (Table 1A); 8 are not (Table 1B).
- Non-`REA_` environment reads (Table 1C): non-test `src/` scanned for `process.env`, `environment.`, `env.`, and `hostEnvironment.` access. A first pass that missed `environment.NAME` was corrected; the list below is from the corrected scan.
- Dynamic names: one template-built read exists, `REA_VERIFY_${client}_COMMAND` (`scripts/verify-native-agent-client.mjs:26`). No other template-built `REA_` name was found.
- Test/CI names (Table 1D): an env read, a child-environment assignment, or a `$env:` / shell reference in `scripts/`, `tests/`, or `.github/`. Purposes come from the reading line. A cell says "uncertain" where the line does not establish the purpose.
- "Kind": `read` = runtime reads its value; `set` = runtime writes it into a process environment; `read-back` = runtime reads it from a child process environment.
